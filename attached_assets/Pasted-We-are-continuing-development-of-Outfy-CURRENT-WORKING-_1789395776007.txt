We are continuing development of Outfy.

CURRENT WORKING STATE:

- Real activities can be created and published.
- Users can see their created activities in Profile -> My Plans.
- Activity Detail works.
- Join / Leave works with real memberships.
- Past start dates/times cannot be published.
- Share works.
- Explore/Search currently does NOT reliably show/search the real published
  activities.

We now need to connect EXPLORE / SEARCH to REAL activity data.

==================================================
MAIN GOAL
==================================================

A user should be able to:

Explore
-> see real upcoming activities
-> search for a published activity
-> tap the result
-> open /activities/:id
-> join it from Activity Detail using the already working membership flow

Example test:

Account A publishes:
"Prueba Outfy"

Account B opens Explore and searches:
"Prueba Outfy"

Expected:
the real activity appears.

==================================================
DEFAULT EXPLORE RESULTS
==================================================

Without a search query, return real discoverable activities.

For this MVP, return only activities that are:

status = active

AND:

starts_at > current server time

Do NOT show:

- cancelled activities
- completed activities
- activities whose start time is already in the past

Do NOT mutate their database status.

This is only a discovery filter.

==================================================
SEARCH
==================================================

Support a text query, for example:

GET /api/activities?search=Prueba%20Outfy

Search should be:

- case-insensitive
- partial-match friendly

At minimum search:

- activity title

Also support useful matching against:

- city

If it can be done cleanly with the existing query structure, also include:

- description

But TITLE search is mandatory.

Examples:

Activity:
"Partido de fútbol en Zaragoza"

Search:
"fútbol"
-> match

Search:
"zaragoza"
-> match if city is Zaragoza

Search:
"partido"
-> match

Do NOT build fuzzy-search infrastructure or install a search dependency.

No Elasticsearch.
No external search service.

==================================================
SEARCH INPUT SAFETY
==================================================

Trim search text.

Apply a sensible maximum search length.

Do not build raw SQL strings from user input.

Use safe Supabase query methods.

Do not expose database errors.
