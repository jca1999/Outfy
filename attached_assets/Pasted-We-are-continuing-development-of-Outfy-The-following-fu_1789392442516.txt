==================================================
IMPORTANT ARCHITECTURE
==================================================

Preserve the existing architecture:

Frontend
-> authenticated Outfy API
-> privileged server-side Supabase client
-> trusted RPC

The frontend must NEVER:

- call Supabase directly
- call the membership RPC directly
- send a user ID
- choose a membership role

The API derives the current user exclusively from the authenticated Outfy
session.

==================================================
GOAL 2 — JOIN ENDPOINT
==================================================

Add:

POST /api/activities/:id/join

Authentication is required.

The endpoint must:

1. Validate the activity route ID.
2. Get the authenticated user's ID from the current Outfy session.
3. NEVER accept userId in the body.
4. Call ONLY:

public.join_activity_as_user

with:

p_activity_id = route ID
p_user_id = authenticated session user ID

Do NOT directly insert into activity_members.

==================================================
JOIN RPC RESULT MAPPING
==================================================

Handle each database result explicitly.

"joined"

Return HTTP 200 with conceptually:

{
  result: "joined",
  memberCount,
  maxParticipants
}

"already_member"

Treat this safely and idempotently.

Return HTTP 200 with:

{
  result: "already_member",
  memberCount,
  maxParticipants
}

"full"

Return HTTP 409 with a stable safe error code:

activity_full

"not_active"

Return HTTP 409 with:

activity_not_active

"not_found"

Return HTTP 404.

Unexpected database/RPC error:

Return HTTP 500 using the existing safe API error conventions.

NEVER return raw Supabase/Postgres errors to the browser.

==================================================
GOAL 3 — LEAVE ENDPOINT
==================================================

Add:

DELETE /api/activities/:id/membership

Authentication is required.

The endpoint must:

1. Validate the activity ID.
2. Derive the user ID from the authenticated session.
3. Call ONLY:

public.leave_activity_as_user

Do NOT directly delete activity_members rows.

==================================================
LEAVE RESULT MAPPING
==================================================

"left"

Return HTTP 200:

{
  result: "left",
  memberCount,
  maxParticipants
}

"not_member"

Treat normal repeated leave safely/idempotently when possible.

Return a safe HTTP 200 state response if the activity exists.

If the RPC result indicates the activity itself did not exist, use 404.

"organizer_cannot_leave"

Return HTTP 409 with stable code:

organizer_cannot_leave

Unexpected failure:

500 with safe generic API error.
