==================================================
ACTIVITY MODEL TO PLAN
==================================================

We want a flexible activity model that can represent:

- football
- cinema
- concerts
- hiking
- going for a walk
- drinks
- restaurants
- gaming
- online activities
- travel
- other social plans

Common activity data should include conceptually:

IDENTITY
- id
- creator_id
- title
- description

CLASSIFICATION
- category
- subcategory

TIME
- starts_at
- ends_at optional

LOCATION TYPE
- physical
- online

PHYSICAL LOCATION
- country_code where appropriate
- region_code where appropriate
- region_name where appropriate
- city
- city latitude/longitude from known location data when eventually available
- meeting point optional

ONLINE
- online platform/location optional

PARTICIPANTS
- optional maximum participant count

COST
- free
- paid
- each_own
- estimated cost optional
- currency optional

STATUS
- active
- completed
- cancelled

TECHNICAL
- created_at
- updated_at

Do NOT assume that every plan is physical.

Do NOT assume every plan has a participant limit.

Do NOT store translated category names as canonical database IDs.

activity_members

==================================================
SECURITY / RLS PLANNING
==================================================

Review the existing security architecture and recommend appropriate future RLS behavior.

At minimum consider:

ACTIVITIES
- authenticated users can create activities as themselves
- users cannot create activities pretending to be another creator
- activity creators can update their own activities
- activity creators can cancel their own activities
- normal users cannot arbitrarily edit other users' activities
- active public activities will eventually need to be readable by authenticated users

ACTIVITY MEMBERS
- authenticated users can join as themselves
- users cannot add another user arbitrarily
- users can leave activities themselves
- organizers will eventually need controlled participant-management permissions

Do not create these policies yet.
