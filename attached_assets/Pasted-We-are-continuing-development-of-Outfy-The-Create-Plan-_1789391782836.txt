==================================================
DATE VALIDATION
==================================================

The visible date format is:

DD/MM/YYYY

Examples of VALID dates:

15/09/2026
29/02/2028

Examples of INVALID dates:

31/02/2026
29/02/2025
32/12/2026
15/13/2026

When the visible date contains a COMPLETE DD/MM/YYYY value but it is not a
real calendar date:

show:

Spanish:
"Introduce una fecha válida."

English:
"Enter a valid date."

==================================================
TIME VALIDATION
==================================================

The visible time format is:

HH:mm

Valid range:

00:00 through 23:59

Invalid examples:

25:00
18:90
24:30

For invalid COMPLETE time values show:

Spanish:
"Introduce una hora válida."

English:
"Enter a valid time."

This applies independently to:

- Start time
- End time

==================================================
WHEN TO SHOW ERRORS
==================================================

Use user-friendly timing.

1. WHILE TYPING AN INCOMPLETE VALUE

Do NOT immediately show an invalid-value error.

Allow the user to finish typing.

2. ON BLUR

When the user leaves the field:

- if empty and optional:
  no invalid-value error

- if incomplete:
  do not show a misleading "invalid date/time" error unless the user attempts
  to submit/review

- if complete but invalid:
  show the appropriate error

3. ON "REVIEW PLAN"

If the user tries to review the plan:

DATE:
- empty -> preserve existing required-date error
- incomplete -> show "Enter a valid date"
- complete but invalid -> show "Enter a valid date"

START TIME:
- empty -> preserve existing required-start-time error
- incomplete -> show "Enter a valid time"
- complete but invalid -> show "Enter a valid time"

END TIME:
- empty -> valid because optional
- incomplete -> show "Enter a valid time"
- complete but invalid -> show "Enter a valid time"

Do not allow Review Plan while these errors exist.

==================================================
END TIME RELATIONSHIP
==================================================

Preserve the existing validation:

End time must be later than Start time.

Spanish:
"La hora de fin debe ser posterior a la hora de inicio."

English:
"End time must be later than start time."

Priority:

If either time itself is invalid, show the invalid-time message first.

Only compare start/end ordering when BOTH times are valid.
