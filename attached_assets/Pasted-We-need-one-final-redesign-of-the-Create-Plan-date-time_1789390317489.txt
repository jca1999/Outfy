We need one final redesign of the Create Plan date/time controls.

The current native date/time-input approach has caused repeated UX problems.

We now want a robust hybrid approach:

- visible editable TEXT field
- native date/time picker still available
- clicking anywhere in the visible field opens the picker
- user can ALSO type the value manually
- custom visible Calendar / Clock icons
- icons must work on Outfy's dark theme
- no browser-native picker icons visible
- no overlapping native text

==================================================
IMPORTANT ARCHITECTURE
==================================================

Do NOT use the native input type="date" or type="time" as the visible field.

Instead:

1. Use a normal visible text input for the user-facing control.

2. Keep a separate native input:
   - type="date"
   - or type="time"

   only for opening the browser/native picker.

The native picker input must be visually hidden but still usable through a ref.

Do NOT use display:none if that prevents showPicker().

It can be positioned safely out of the visible UI or made fully transparent.

==================================================

IMPORTANT:

Do NOT change the existing underlying form state format.

==================================================
DATE MANUAL INPUT
==================================================

Allow manual typing in:

DD/MM/YYYY

Example:

15/09/2026

Keep separate local display text if necessary.

When the value becomes a valid date:

15/09/2026

convert it internally to:

2026-09-15

and update:

form.date

Use simple local parsing.

Do NOT install a date library.

Validate:

- exactly valid day/month/year
- actual real calendar date

Examples:

31/02/2026 -> invalid
29/02/2025 -> invalid
29/02/2028 -> valid

Do not silently convert invalid dates into different dates.

If the typed value is incomplete, allow the user to continue typing without
immediately destroying the text.
