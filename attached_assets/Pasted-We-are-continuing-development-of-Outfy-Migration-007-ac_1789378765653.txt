ISSUE 2 — RLS auth.uid() PERFORMANCE
==================================================

Supabase's performance advisor reported auth_rls_initplan warnings on the new activity policies.

The policies currently call:

auth.uid()

directly.

Update ONLY the activity-related RLS policies so auth.uid() is evaluated through:

(select auth.uid())

where appropriate.

Preserve the EXACT existing authorization behavior.

The affected policies are:

PUBLIC.ACTIVITIES

1.
"Authenticated users can view available activities"

Existing behavior:
- active activities are visible
- creator can also see their own non-active activities

2.
"Authenticated users can create their own activities"

Existing behavior:
- creator_id must equal authenticated user

3.
"Creators can update their own activities"

Existing behavior:
- only creator may update
- ownership must remain the authenticated user

PUBLIC.ACTIVITY_MEMBERS

4.
"Authenticated users can view visible activity members"

Preserve:
- membership rows are visible for active activities
- creators can see memberships for their own activities

5.
"Authenticated users can join activities as participants"

Preserve:
- user_id must be authenticated user
- role must be participant
- activity must be active

6.
"Participants can leave activities"

Preserve:
- user can delete only their own membership
- role must be participant
