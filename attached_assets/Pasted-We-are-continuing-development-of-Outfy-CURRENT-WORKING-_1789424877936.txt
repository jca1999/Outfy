==================================================
WHAT BELONGS IN HISTORY
==================================================

Include an activity when:

starts_at <= current server time

AND the current user is related to it as either:

A) organizer / creator

OR

B) participant through public.activity_members

This means History should show:

- activities created by the user that have already started/passed
- activities created by somebody else where the current user participated
  and the activity has already started/passed

==================================================
IMPORTANT — NO DUPLICATES
==================================================

The organizer also exists in activity_members.

Therefore:

an activity created by the current user MUST appear only ONCE in History.

Do not show the same activity twice because the user is both:

creator
and
activity_member organizer

Deduplicate by activity ID.

==================================================
HISTORY DOES NOT REQUIRE status = completed
==================================================

IMPORTANT:

Do NOT depend only on:

status = completed

The current system may still have an old activity with:

status = active

even though its starts_at is already in the past.

For this first History version, the main rule is:

starts_at <= NOW

Do NOT automatically modify its database status.

Do NOT implement automatic completed transitions in this task.

We can handle lifecycle/status automation later.

==================================================
CANCELLED ACTIVITIES
==================================================

Include cancelled activities in History if:

- the user created them
OR
- the user participated in them

AND they are already past.

Display their real:

status = cancelled

Do NOT silently remove them.

Do NOT convert status values.
