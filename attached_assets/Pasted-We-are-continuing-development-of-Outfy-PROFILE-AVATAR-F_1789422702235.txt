==================================================
MAIN GOAL
==================================================

Implement the COMPLETE first version of profile avatar customization:

1. User selects an image.
2. User sees a crop editor BEFORE uploading.
3. User can move/reposition the image.
4. User can zoom in/out.
5. User can see how the avatar will look as a circle.
6. User confirms.
7. Browser generates a cropped 512x512 WebP.
8. ONLY that processed WebP is sent to the Outfy API.
9. API uploads it to the private Supabase avatars bucket.
10. profiles.avatar_path is updated.
11. Profile immediately displays the new avatar.
12. User can later replace it.
13. User can remove it and return to the existing default/initials avatar.

The ORIGINAL source image must NEVER be uploaded to Supabase.

==================================================
IMAGE OUTPUT
==================================================

When saving:

Generate a new Canvas output at exactly:

512 x 512 pixels

Draw ONLY the selected cropped region.

Encode as:

image/webp

Start with approximately:

0.82 quality

The final Blob must be:

- image/webp
- <= 1048576 bytes

Do NOT upload the original source file.

==================================================
OUTPUT SIZE SAFETY
==================================================

512x512 WebP should normally be far below 1 MiB.

Still verify the generated Blob size.

If it is over 1 MiB:

retry encoding at progressively lower reasonable WebP quality.

Do not reduce below a visibly poor quality without reporting an error.

A simple quality fallback such as approximately:

0.82
0.75
0.68

is enough.

Do NOT build complex compression infrastructure.

If it still exceeds 1 MiB:

show a friendly processing error and upload nothing.

==================================================
IMAGE ORIENTATION
==================================================

Use normal modern browser image decoding so mobile photos display in their
correct visual orientation.

Do not manually rotate images unless current browser decoding requires it.

Do not introduce an EXIF dependency unless absolutely necessary.

==================================================
BACKEND API
==================================================

Implement authenticated endpoints following the EXISTING Profile API route
conventions.

Recommended semantics:

If the project has a better established `/api/me/...` convention, follow that

==================================================
UPLOAD REQUEST
==================================================

Preferred upload payload:

raw image/webp request body

because the browser already sends the FINAL processed WebP.

Do NOT wrap the image in base64 JSON.

Do NOT send the original image.

If the existing server framework has a safe established multipart mechanism,
it may be reused, but do NOT add a multipart dependency solely for one processed
blob if raw binary bodies are straightforward.

==================================================
UPLOAD BACKEND SECURITY
==================================================

Authentication required.

Derive user ID ONLY from the existing Outfy authenticated server session.

The browser must NEVER send:

userId
profileId
avatarPath

as trusted identity information.

Canonical path MUST be constructed SERVER-SIDE:

`${authenticatedUserId}/avatar.webp`

==================================================
SERVER VALIDATION
==================================================

Before uploading verify:

1. authenticated session exists
2. content type is exactly image/webp
3. body is not empty
4. body <= 1048576 bytes
5. binary content actually resembles a WebP file

At minimum verify WebP container signature:

bytes 0-3:
RIFF

bytes 8-11:
WEBP

Do NOT trust Content-Type alone.

Reject invalid content safely.

Do not expose raw Supabase/Postgres errors.

==================================================
STORAGE UPLOAD
==================================================

Upload through the EXISTING privileged server-side Supabase client to:

bucket:
avatars

path:
{authenticatedUserId}/avatar.webp

Use overwrite/upsert behavior.

The user should NOT accumulate:

avatar1.webp
avatar2.webp
avatar3.webp

There is only one canonical avatar object per account.

Set:

contentType = image/webp

==================================================
DATABASE UPDATE
==================================================

Only after successful Storage upload:

update the authenticated user's:

public.profiles.avatar_path

to exactly:

{authenticatedUserId}/avatar.webp

Never accept the path from the frontend.

==================================================
FAILURE CONSISTENCY
==================================================

If Storage upload succeeds but updating profiles.avatar_path fails:

perform best-effort cleanup or otherwise ensure the API does not falsely report
success.

Do not leave the profile pointing to an invalid file.

Return a safe generic error.

==================================================
PRIVATE AVATAR READ
==================================================

The avatars bucket is PRIVATE.

Do NOT change it to public.

To display the current user's avatar:

server reads profiles.avatar_path.

If NULL:
return avatarUrl = null

If present:
generate a temporary signed URL using the privileged Supabase server client.

Use a reasonable lifetime such as:

1 hour

Do NOT persist signed URLs in public.profiles.

Only avatar_path is persisted.

==================================================
GET AVATAR RESPONSE
==================================================

Return conceptually:

{
  avatarUrl: string | null
}

Do not expose service-role information.

Do not expose another user's private data in this task.

This endpoint is ONLY for the authenticated user's own avatar for now.

==================================================
UPLOAD RESPONSE
==================================================

After successful upload return enough information for immediate UI update,
preferably a fresh signed URL:

{
  avatarUrl: "..."
}

The Profile should update immediately without a full-page reload.

==================================================
DELETE AVATAR
==================================================

Authenticated endpoint.

Derive path server-side.

Set:

profiles.avatar_path = NULL

Then remove:

{authenticatedUserId}/avatar.webp

from the avatars bucket.

For consistency, prefer an order that never leaves the profile permanently
pointing to a deleted file.

If object removal fails after the profile path was cleared:

do not restore a broken profile path.

A private orphan at the canonical path is acceptable as a temporary cleanup
issue because the next upload overwrites the same path.

Return success if the user's profile has safely returned to no-avatar state.
