We need to fix a confirmed bug in the Create Plan date/time controls.

I have reviewed the CURRENT implementation in:

artifacts/outfy/src/pages/create-activity.tsx

The root cause is now known.

The current native date/time input is layered above the custom display and
tries to hide Chromium's segmented date/time UI using text-transparent and
multiple ::-webkit-datetime-edit selectors.

This is not reliable.

Chrome is still exposing/focusing internal date/time segments (for example
the blue highlighted "dd"), and the current onPointerDown handler allows
native segmented-input behavior to interfere with showPicker().

DO NOT attempt another pseudo-element patch.

==================================================

  if (typeof input.showPicker !== 'function') {
    return;

  try {

    // Native click/focus remains the fallback.
