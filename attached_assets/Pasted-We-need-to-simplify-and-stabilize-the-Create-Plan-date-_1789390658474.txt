The previous hybrid implementation still has a problem:
the Calendar/Clock picker button does not reliably open the native picker.

We also want proper input masking for manually typed dates and times.

IMPORTANT UX DECISION:

Do NOT make the entire text field open the native picker anymore.

The visible text field is for manual typing/editing.

The Calendar / Clock icon button is the explicit control that opens the native
picker.

This avoids conflict between:
- placing the text cursor
- editing manually
- opening the native picker

==================================================
DATE INPUT MASK
==================================================

Implement a lightweight date mask WITHOUT installing a dependency.

Accept digits from the user and automatically format them as:

DD/MM/YYYY

Examples:

User types:

3
-> 3

31
-> 31/

311
-> 31/1

3112
-> 31/12/

31122026
-> 31/12/2026

If the user pastes:

31122026

it should become:

31/12/2026

If they paste:

31/12/2026

it should remain valid.

Strip irrelevant characters and keep a maximum of 8 numeric digits.

Do not create duplicated slashes.

==================================================
DATE CANONICAL STATE
==================================================

The existing canonical:

form.date

MUST continue using:

YYYY-MM-DD

Do not change publishing logic.

Use a separate visible text state if necessary.

Example:

visible:
31/12/2026

canonical:
2026-12-31

Only update form.date when the visible value represents a COMPLETE AND VALID
calendar date.

Validate real dates.

Examples:

31/02/2026 -> invalid
29/02/2025 -> invalid
29/02/2028 -> valid

Do not let JavaScript Date silently normalize invalid dates.

When the visible date is incomplete or invalid:
- keep the typed visible text
- canonical form.date should not become an invalid date

==================================================
OPEN PICKER RELIABLY
==================================================

The icon button must call showPicker() DIRECTLY from the user event.

Use a helper conceptually equivalent to:

function showNativePicker(input: HTMLInputElement | null) {
  if (!input) return;

  if (typeof input.showPicker === 'function') {
    try {
      input.showPicker();
      return;
    } catch {
      // fallback below
    }
  }

  input.focus();
  input.click();
}

IMPORTANT:

Call this helper synchronously from the icon button's click/pointer event.

Do NOT use:
- setTimeout
- async
- Promise
- requestAnimationFrame

Do NOT rely on clicking an invisible native calendar hotspot.

The custom icon button itself must trigger the picker.
